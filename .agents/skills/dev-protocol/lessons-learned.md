## 1. Invariantes de Arquitectura y Contratos

*(Registrá aquí contratos cerrados, convenciones de interfaz y decisiones de diseño que no deben reabrirse ni revertirse sin consulta explícita).*

- **Roadmap 07–10 cerrado, no reabrir**: las fases 07–10 viven en `roadmap/07_*.md` … `roadmap/10_*.md` y están en DoD. La fase viva nueva es `roadmap/11_SELF_INSPECT.md`. No re-ejecutes `roadmap/archive/` (bootstrap 1–6). El endurecimiento del socket Docker sigue en `roadmap/90_BACKLOG_HARDENING.md`.
- **Socket Docker vigente: bind directo**. `murray-agent` y `openhands` montan `/var/run/docker.sock`. El seam sigue siendo `ops.mjs`. **No** implementes `tecnativa/docker-socket-proxy`, `DOCKER_HOST` a un proxy, ni `userns-remap`. Eso está en `roadmap/90_BACKLOG_HARDENING.md` y solo se abre con orden humana. El TTL de sandboxes usa el socket actual; no es hardenizado.
- **Estado de Murray ≠ Postgres**: n8n usa PostgreSQL 16. El estado de `murray-agent` es SQLite WAL (`murray.db` en `murray_agent_data`). Tablas: `jobs`, `hitl_tokens`, `session_context`, `seen_emails`, `garfio_rationales`, `operator_notes`. Motor `node:sqlite` (Node 22), no `better-sqlite3`. No lo pases a Postgres. `postgres_db` nunca entra en auto-recreate de inspect.
- **Gemini ≠ OAuth Gmail**: `GEMINI_API_KEY` es AI Studio. No reuses `GOOGLE_REFRESH_TOKEN` / `GOOGLE_CLIENT_SECRET` como key de Gemini. H13 (humano) pega `GEMINI_API_KEY` + `LITELLM_MASTER_KEY`.
- **Gateway LiteLLM**: Murray usa `LITELLM_BASE_URL=http://litellm:4000` + `LITELLM_MASTER_KEY` (está en `agent-net`). El LLM de Garfio corre **adentro del sandbox** `oh-agent-server-*` en el `bridge` default: no resuelve `litellm` y un `WORKSPACE_MOUNT_PATH=./workspace` relativo no monta el repo. Contrato vigente: LiteLLM publicado `127.0.0.1:4000`; `LLM_BASE_URL`/`OPENAI_BASE_URL=http://host.docker.internal:4000`; `OPENAI_API_KEY` = master; mount absoluto `COMPOSE_PROJECT_DIR/workspace`. Inventario: `roadmap/91_PERMISSIVE_WINDOW.md`. `LLM_MODEL=openai/garfio-worker`. `startConversation` pasa por `openHandsLlmModel()` y manda **solo** `secrets.OPENAI_API_KEY` (`conversationSecrets()`). OpenHands 1.36 reserva el prefijo `LLM_` en nombres de secreto: `secrets.LLM_API_KEY` → start-task ERROR / poll `start_error`. Un alias pelado explota `LLM Provider NOT provided`; key ausente explota `OPENAI_API_KEY must be set`. Alias extra `openai/garfio-worker` / `openai/deepseek-chat` en el YAML por si el SDK no strippea. Imagen pin `ghcr.io/berriai/litellm:v1.99.1`. Health `GET /health/liveliness`. Carta Gemini: `gemini-3.8-flash` → `gemini-2.5-flash-lite`. No `gemini-2.5-flash`. No Pro en default/fallback.
- **HITL bypass de ventana**: `MURRAY_HITL_BYPASS=code,clone` saltea el teclado de clone/código. Push y delete siguen pidiendo Aprobar. Inspect (P12) corre retry/heal/restart/recreate **sin** teclado; `propose_ops` del chat **sí** pide Aprobar. `MURRAY_TELEGRAM_QUIET=1` corta notify de **progreso**. Pausa, tranca, fin e inspect terminal sí suenan (`terminal: true`). Revertir P6/P7/P12 en hardening 91.

- **Contratos de Interfaz**: Las interfaces públicas son el límite de prueba (seam). Si una prueba requiere inspeccionar el estado interno de un módulo, la abstracción es incorrecta.
- **Manejo de Secretos**: Ningún token, contraseña ni clave privada se escribe en código, git, logs, handoffs ni chat. Credenciales solo en `.env` y `config/mcp-auth/.gauth.json` (gitignore). Un handoff que pegue `GOOGLE_CLIENT_SECRET` / refresh token **es un incidente**: rotar el secret en Google Cloud Console, actualizar esos dos archivos, `docker compose up -d --force-recreate workspace-mcp`. No reimprimir el valor.
- **n8n HITL ChatID**: el filtro `$env.TELEGRAM_CHAT_ID` solo funciona si esa variable está inyectada en el servicio `n8n` de Compose. El JSON del workflow no alcanza. En n8n 2.x también hace falta `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`.
- **workspace-mcp draft-only**: `GMAIL_ALLOW_SENDING=false` y `GMAIL_ALLOW_DRAFTS=true` son invariantes. El paquete npm `@j3k0/mcp-google-workspace` no está publicado; el seam HTTP vive en `config/workspace-mcp/server.mjs` + `gmail-client.mjs` y rechaza cualquier ruta de send. Gmail API real: `status=ok` (inbox vacía inclusive). OAuth ausente = `503`, nunca `unread_count=0` fingido ni `awaiting_oauth`.
- **docker compose restart no recarga `.env`**: el contenedor viejo sigue con el env del create. Después de cambiar secretos o `working_dir`: `docker compose up -d --force-recreate <servicio>`. `restart` solo SIGTERM/SIGSTART el mismo container.
- **Gmail `unauthorized_client`**: el `refresh_token` nació de **otro** OAuth Client ID (casi siempre Desktop vs Web). No se “arregla” recreando el contenedor. Hay que reautorizar en el Playground con el cliente Web que está en `.env`. El shim reintenta una vez con `config/mcp-auth/.gauth.json` si ese client_id es distinto; si env y gauth son el mismo cliente, Google sigue diciendo mismatch.
- **architecture_spec.md es contrato vivo**: si no existe, crearlo. Si cambia un shape HTTP, un webhook, un guardrail o un presupuesto, actualizarlo en el mismo cambio. El stub `awaiting_oauth` / `stub_until_oauth` no puede volver a ese archivo.
- **Un bot Telegram = un webhook**: `email_triage_draft` no lleva `telegramTrigger`. Los callbacks siguen en `telegram_hitl_router`. El schedule pregunta a Murray `POST /triage/filter` y, solo tras draft 2xx, `POST /triage/mark-seen`. Sin eso, cada 15 min duplica borradores. No hay `staticData.seen` ni estado de vistos en `workspace-mcp`. H14 (humano) tiene que reimportar + publicar el JSON; si no, el cron viejo sigue.
- **OpenHands registry**: `docker.all-hands.dev` resuelve NXDOMAIN. Imagen vigente: `ghcr.io/openhands/openhands:latest` (puerto 3000, workspace `/opt/workspace_base`).
- **OpenHands HITL**: el UI local responde HTML en `/api/conversations` (POST → 405). Crear conversación: `POST /api/v1/app-conversations`. Rechazar/Pausar no deben pegarle a OpenHands. H12 cubrió **Rechazar**. **Aprobar** (OpenHands + DeepSeek) sigue siendo prueba humana, no DoD de código.
- **n8n no recarga `./workflows`**: el mount es referencia. Un JSON nuevo no cambia el flujo publicado. Import + `publish:workflow` + `docker compose restart n8n`. `import:workflow --userId` y `--projectId` son mutuamente excluyentes. Todo JSON de workflow importado vía CLI requiere un campo `"id"` raíz no nulo; si falta, Postgres aborta `null value in column "id" of relation "workflow_entity" violates not-null constraint`. IDs publicados: HITL `20uYWal9fr2bWwVV`, triage `Z8f9K2mP1qRt5vWx`.
- **OAuth Playground: cuatro trampas, no un bug de código**: (1) typo de una letra en `GOOGLE_CLIENT_ID` → `401 invalid_client` / “The OAuth client was not found”. (2) secret OCR/rotado de otra tanda, largo distinto. (3) el engranaje ⚙️ guarda Client ID/secret en **localStorage**; corregir `.env` no alcanza, hay que pegar el par Web otra vez en el Playground. (4) el `code=4/...` caduca ~60s o al reutilizarlo → `400 invalid_grant`; reautorizar Paso 1 y canjear **ya**. El `refresh_token` tiene que nacer del cliente **Web**, no del Desktop.
- **405 fósil en logs de n8n**: `docker compose logs --tail=50 n8n` mezcla Axios 405 de *antes* del SIGTERM con el proceso actual. H12 / HITL vivo se verifica con `docker compose logs --since "$(docker inspect -f '{{.State.StartedAt}}' murray-n8n)"` y/o `execution_entity.startedAt` posterior al publish. El grafo publicado tiene que tener el nodo `¿Aprobar OpenHands?`.
- **`working_dir` no puede ser un bind `:ro`**: `workspace-mcp` monta `./config/workspace-mcp` → `/opt/mcp:ro`. Si `working_dir=/opt/mcp`, Docker Desktop aborta healthcheck y `compose exec` con *cwd outside of container mount namespace* (`exit=-1`). El proceso HTTP sigue vivo → `ps` dice `unhealthy` y el test live falla. Cwd canónico: `/tmp`. Command: `node /opt/mcp/server.mjs`. Tests y exec: `-w /tmp`.
- **`PROGRESS.md` no es un diario de bloqueos muertos**: si OAuth ya está live y el triage `active=t`, no dejar escrito “mismatch bloquea Active”. El operador lee eso como trabajo pendiente.
- **Telegram chat vs sandbox**: texto libre va a `murray-agent` (DeepSeek). El teclado OpenHands **crudo** solo si el mensaje es `/oh` o `sandbox:`. Clone/edits pedidos a Murray usan HITL `APPROVE_CLONE`/`APPROVE_CODE` y el obrero OpenHands.
- **Coding sessions**: un repo activo por chat en `./workspace/<slug>`. Solo `https://github.com|gitlab.com`. Clone shallow; pull/push unshallow. `git push` exige HITL + `allowPush` y **nunca** `main`/`master` ni `--force`. Delete de cualquier path bajo `./workspace` exige HITL. Token privado: `GITHUB_TOKEN`/`GITLAB_TOKEN` vía `http.extraHeader`, nunca en la URL ni logs. Author default `Murray <murray-threepwood@users.noreply.github.com>`. n8n timeout de `/chat` es 45s → jobs async + `sendMessage` del mismo bot (`TELEGRAM_CHAT_ID` only).
- **HITL sin teclado = prosa del LLM, no n8n roto**: el IF `!!$json.needs_hitl` manda a **Enviar Teclado Ops** solo con flag. DeepSeek puede escribir «Pido Aprobar» / «necesito que apruebes» / «¿te re-disparo propose_code_mission?» **sin** invocar la tool. `/chat` recupera HITL si hay comando de test (mensaje actual, último assistant o `lastTestCommand`); si no, receta Murray, nunca prosa de Aprobar. `si`/`dale`/`ok` confirma el plan previo. Mutación sin `Comando:` no va al LLM. `Test:` cuenta. `\bpush\b` suelto no es pusheá. Clone/delete/pusheá/checkout interceptan solos. El job de código arranca al aprobar el teclado.
- **`/jobs` no es `docker logs`**: lista la tabla `jobs` de `murray.db` (clone/code/git/delete/oh_poll/inspect). El «log» son notify de Telegram + `status=done|failed|stuck|paused`, cap 40 guardadas / 20 al mostrar. No sustituye `/logs n8n`. Slash e intercept de **lista** («estado de los jobs», `/jobs`, `/jobs <id>`), sin LLM. Reloj y duración salen de `createdAt` (America/Montevideo); `updatedAt` miente en `oh_poll` porque el worker lo toca cada ~2s. Id Murray = 16 hex; conversation/start-task OpenHands = 32 hex: `find` acepta los tres. Un UUID pegado o «en qué quedó task …» / «qué pasó» / `/triage` encolan job `inspect` (dump redacted + modelo + auto-ops). JSON `jobs.json` / `memory.json` / `session.json` solo existen como origen de migración one-shot (`*.migrated`).
- **Inspect no es Cursor de murray-infra**: el agente lee CHANGELOG/CONTEXT/91/conductor `:ro` y escribe `operator-inbox/` (append-only, redactado). No monta `.git` ni `.env` extra. No hace `git commit` del inbox. El JSON del modelo no puede pedir `docker exec`, `down`, editar `.mjs` ni push a main: eso vira a `operator_task`. Auto-ops solo con finding. Schema inválido → fallback + nota `llm_inspect_unparseable`.
- **Heal de obrero no es `docker rm` libre**: `heal_openhands` solo borra contenedores `oh-agent-server-*` (nombre, no ancestor `runtime`) y reinicia `openhands`. `propose_ops` no tiene ese action. Inspect lo corre sin HITL (P12). El panel `el_corazon` opción 3 usa el mismo filtro de nombre.
- **OpenHands `sandbox PAUSED` no es done**: `execution_status` null + sandbox PAUSED no pasa `isAgentDone`. Árbol sucio → job `paused` + aviso de commit. Limpio o repo ausente → stuck HITL `sandbox_paused`, nunca «misión lista». `finished` + git vacío **sin** commits ahead de `main`/`origin/main` → `empty_finish`. `finished` + commits locales (porcelain limpio) es misión lista: el obrero ya commiteó. Reloj `detectStuck` 12 min **no** aplica si sandbox `RUNNING`; tope duro 4 h. Avisar al CEO al pausar, trancar y terminar, no solo si pregunta.
- **Kick de jobs es exclusivo**: `enqueue` + `drain` no pueden correr el mismo job dos veces. Un segundo `kick` espera el promise en vuelo. Sin eso, un `code` job abre dos `oh-agent-server` y OpenHands responde 429.
- **TTL de sandbox no reemplaza heal**: watcher 5 min / 30 min y el hook al kick `code` purgan `oh-agent-server-*` huérfanos o viejos si no hay job en vuelo. No hacen `restart openhands`. No es `docker rm` libre ni un socket-proxy. El socket sigue montado en `murray-agent` y `openhands`.
- **Poll HTTP error 23 es ruido**: un fallo de `getConversation` reencola sin notify. Tres seguidos → stuck `poll_error:…` + teclado. No dejar el `error:` del job en cada reintento transitorio.
- **Jail `./workspace` en macOS**: `path.resolve(/var/...)` y `fs.realpathSync` (`/private/var/...`) no son el mismo string. Comparar contra el realpath de la raíz; si no, `rm` de un hijo jailed explota `workspace_jail`.
- **OpenHands 1.11 API**: health `GET /health` (`"OK"`). `GET /api/health` es HTML de la SPA. Alta `POST /api/v1/app-conversations` (start task). Follow-up `POST /api/v1/app-conversations/{id}/send-message`. Eventos `GET /api/v1/conversation/{id}/events/search`. `execution_status` incluye `stuck`. Circuit breaker real está en `detectStuck` (status/timeout/loop), no solo en el script simulado.
- **`approval_id` ops de un uso**: `POST /ops/execute` sin token vigente es `403`. Telegram `callback_data` ≤64 bytes → id hex de 16 chars (`APPROVE_OPS:<hex>`). Restart/recreate **no** pasan por el LLM.
- **docker.sock en murray-agent**: el seam es `ops.mjs` (allowlist + `assertSafeComposeArgs`). Nunca `down -v` / `exec`. Recreate con `--no-deps`. `heal_openhands` es el único `docker rm -f`, y solo IDs de `oh-agent-server-*`. `--project-directory /opt/stack` monta `docker-compose.yml` + `.env` (el LLM no puede `cat` .env: no hay tool de shell).
- **Notificaciones terminales y `MURRAY_TELEGRAM_QUIET`**: `telegram.send` saltea mensajes cuando `quiet && !terminal`. Por lo tanto, TODO estado final o de resolución de tarea asíncrona (`handlePullJob`, `handleCheckoutJob`, `handlePushJob`, `handleDeleteJob`, `handleCloneJob`, `handlePollJob` fin/tranca) DEBE emitirse con `terminal: true`. Dejarlo sin ese flag provoca que el usuario quede en silencio absoluto en Telegram esperando tareas que ya concluyeron y obligándolo a inspeccionar `/jobs`.
- **Modo Mal Manager (Monitoreo de Obrero en Sandbox)**: Para seguir a un obrero como Garfio en tiempo real sin saturar con spam ni paredes de texto, desacoplar el sondeo rápido (4s) del reporte al CEO (intervalo configurable: 30s, 1m, 2m, 5m, 10m, 30m). Extraer quirúrgicamente solo la actividad reciente (archivo editado, comando bash + exit code, pensamiento condensado) y envolverlo en el personaje de Murray con formato esquemático corto de fácil lectura en Telegram.
- **Bind `./workflows` a veces vacío hasta recrear n8n**: Docker Desktop puede servir `/opt/workflows` vacío. Workaround: `docker compose cp workflows/foo.json n8n:/tmp/foo.json` e importar desde `/tmp`. Un restart de n8n suele remountar.
- **OpenHands v1 FinishAction & Rationale**: en OpenHands SDK v1 / 1.36.0, el reporte final del obrero no viaja en `event.payload.content`, sino como `ActionEvent` con `tool_name: "finish"` y `event.action.message` (`FinishAction`). Parsearlo siempre junto con variantes de encabezados markdown (`#{2,4}\s*...`). Si falta, el bot notifica en silencio y vacía la bitácora SQLite.
- **Sandboxes efímeros no son fallos de stack (`sandbox_status: MISSING`)**: al concluir una tarea (`execution_status === "finished"` o `job.status === "done"`), el runtime de OpenHands destruye el contenedor sandbox; su status pasa a `MISSING`. Esto es el ciclo nominal. `inspect.mjs:healBacked()` nunca debe disparar `heal_openhands` ni reiniciar el servicio si la conversación ya terminó o el job en curso está resuelto. Tampoco jobs stuck fósiles de horas atrás deben contaminar snapshots actuales.
- **Consultas de avance funcional ≠ Triage de infraestructura**: preguntas como *«qué hizo garfio»*, *«en qué está el repo»*, *«qué está hecho»* o *«qué hay para hacer»* son consultas de estado y roadmap de proyecto, jamás deben rutearse al motor de triage/inspect de Compose. Triage es exclusivamente para incidentes de stack.
- **Simetría de comandos de barra diagonal (`/push`, `/pull`, `/estado`, `/roadmap`)**: en Telegram, todo comando operacional disponible en lenguaje natural debe tener su contraparte idéntica como slash command (`/push`, `/pull`, `/commit`, `/diff`, `/estado`, `/roadmap`). Si `parseSlash` rechaza un comando de barra como inexistente, impide que el usuario actúe sobre las directivas que el propio bot le pide.
- **Comando `/estado` con trigger directo de PUSH HITL**: `/estado` provee visión 360° del repo (rama, commit, tests pasados, tickets de roadmap terminados vs pendientes) y, si `commitsAhead > 0`, emite automáticamente el teclado inline HITL (`[ 🚀 Aprobar Push & Abrir PR ] [ ❌ Rechazar ]`) para evitar fricción y permitir abrir PR con un solo tap.
- **Git Smart HTTP sobre HTTPS en GitHub (`http.extraHeader`)**: Git Smart HTTP en `github.com` rechaza cabeceras `Authorization: Bearer <token>` con `fatal: could not read Username for 'https://github.com': terminal prompts disabled` (exit code 128). Exige estrictamente `Authorization: Basic ${Buffer.from('x-access-token:' + token).toString('base64')}`.
- **Restricción de refspec en clones `--single-branch`**: Los repos clonados con `--single-branch` fijan `remote.origin.fetch = +refs/heads/main:refs/remotes/origin/main` en `.git/config`, ignorando el tracking de ramas creadas posteriormente. `ensureHistory` debe reconfigurar `remote.origin.fetch = +refs/heads/*:refs/remotes/origin/*` para que el seguimiento de branches (`origin/feat/...`) opere sin errores.
- **Apertura de Pull Requests idempotente (GitHub REST API)**: `createOrGetPullRequest` crea PRs vía `POST /repos/:owner/:repo/pulls`. Si responde 422 ("already exists"), consulta `GET /pulls?head=owner:branch&state=open` y recupera el PR existente de forma transparente, devolviendo el enlace directo en Telegram.
- **Falsos positivos destructivos en Regex de `DELETE_INTENT`**: Una regex sin anclar (`/borr[áa]|elimin[áa]/i`) captura palabras legítimas en instrucciones de refactor o code reviews (como *«eliminá la función X»*, *«el clamping borraba micro-gaps»*). `DELETE_INTENT` debe estar estrictamente anclado al inicio del comando o exigir contexto explícito de workspace (`/^(?:por favor\s+)?(?:borr[áa]r?|elimin[áa]r?|delete|\brm\b)(?:\s+(?:el\s+)?(?:workspace|repo|directorio|carpeta|archivo)...$/i`), impidiendo que un prompt técnico sea secuestrado con *«¿Qué borro bajo ./workspace?»*.
- **Extracción resiliente de comandos de prueba (`extractTestCommand`)**: La detección de comandos de test en lenguaje natural debe contemplar ejecutores bare (`pytest backend/tests/test_foo.py` sin exigir `uv run`), bloques con backticks (`` `pytest ...` ``), y filtrar sufijos conversacionales en español (*«... dé verde posta, y volvé a subir»*), previendo que la instrucción completa viaje intacta al sandbox de Garfio.
- **`git config` local vs flags globales y excepciones síncronas en wrappers**: Prohibir `config` en `GIT_FORBIDDEN` bloquea la identidad de commit (`user.name`, `user.email`) y el fetch de refspecs (`remote.origin.fetch`) locales del workspace. La restricción debe apuntar a flags globales/sistema (`--global`, `--system`, `--file`, `--blob`). Asimismo, wrappers de spawn que retornan promesas (`defaultGitRun`) deben ser `async function` para que validaciones que hagan `throw` devuelvan rechazos de promesa capturables con `.catch()`, en lugar de arrojar excepciones síncronas que cortan la ejecución antes de asignar handlers.
- **Sanitización Universal Telegram HTML y fallback ante 400 (`escapeTelegramHtml`)**: Todo mensaje hacia Telegram Bot API debe utilizar `parse_mode: 'HTML'` y sanitizar caracteres reservados (`<`, `>`, `&`). Si Telegram rechaza con HTTP 400 (`can't parse entities`), `createTelegramNotifier` reintenta automáticamente con el texto sanitizado como fallback de texto seguro. En bloques `<pre>` (como en `/diff`), el contenido interno debe pasar siempre por `escapeTelegramHtml` con `{ rawHtml: true }` para evitar que fragmentos de código con etiquetas o comparaciones (`<iostream>`, `<div>`, `a < b`) rompan el parseo de entidades de Telegram.

## 2. Integraciones Externas y Protocolos

*(Registrá aquí peculiaridades de APIs externas, modelos LLM, bases de datos o servicios de red).*

- **Determinismo en Tests de LLM**: Las pruebas automatizadas nunca deben depender de llamadas en vivo a APIs de modelos con muestreo no determinista. Usar siempre mocks, stubs o fixtures grabados.
- **Timeouts y Circuit Breakers**: Toda llamada HTTP saliente a servicios externos debe definir un timeout explícito y un mecanismo de corte ante fallos reiterados.
- **Compose v5 quotes**: `docker compose config` emite `GMAIL_ALLOW_SENDING: "false"` (comillas dobles). Un grep que busque `'false'` con comillas simples falla en Compose 5.x; parsear YAML/JSON.
- **cloudflared placeholder**: un token de ejemplo deja el proceso `running` con `Failed to get tunnel`. No es un crash; el hostname público no existe hasta H3–H4 del operador. El token real de este stack ya está: si *vuelve* ese log, el túnel está mal, no es “esperado”. Recreates de n8n dejan un `connection refused` a `:5678` en logs del túnel; es el gap del restart, no un hostname roto. Verificar `curl -I https://ceo.threepwood.uy/healthz`.
- **Postgres 16 vs n8n 2.38**: n8n alerta `Upgrade to Postgres 17`. No subir de major sin OK humano: rompe el volumen `postgres_data`.
- **Gmail en Google Cloud**: habilitar **Gmail API**, nunca **Gmail MCP API**. El MCP de este stack es `workspace-mcp`, no un producto de Google. Consent OAuth 2026: **Google Auth Platform** → **Público** → **Usuarios externos** (Gmail personal). **Interno** solo con Google Workspace. No verificar ni publicar la app; test user = el CEO.
- **OAuth Testing ≈ refresh token de 7 días**: app en **Prueba** (externa, sin publicar) → Google caduca el `refresh_token` ~7 días → `503 gmail_oauth_failed` / `invalid_grant`. Mitigación operativa: reautorizar en Playground (engranaje Web, canje inmediato) y `force-recreate workspace-mcp`. Publicar/verificar la app **no** es el default: scopes Gmail piden revisión de Google.
- **OAuth Playground + Desktop = `redirect_uri_mismatch`**: el Playground redirige a `https://developers.google.com/oauthplayground`. H8.4 es cliente **Web** con esa URI en **redirect URIs**, no en JavaScript origins (el origin no admite path). El `GOOGLE_REFRESH_TOKEN` nace de ese Client ID. Access type Offline en el engranaje.
- **OAuth Playground Step 1 no tiene Add**: abrir **Gmail API v1** y tildar readonly + compose, o pegar las dos URLs en `Input your own scopes` **separadas por un espacio** y **Authorize APIs**. Un token, los dos scopes.
- **Telegram HITL webhookId**: n8n 2.38 registra `POST /webhook/<webhookId>/webhook`. Telegram pegando `.../telegram trigger/webhook` da 404. Trigger sin `webhookId` + UUID huérfano da 500 `reading 'node'`. El JSON canónico tiene que incluir `webhookId` `4dae132d-912c-40e0-b048-c00b42e03250`.
- **n8n Telegram Markdown por default**: `GenericFunctions.js` pone `parse_mode=Markdown` si el nodo no lo declara. `REJECT_TASK` tiene `_` → Telegram 400 `can't parse entities`. Los nodos send/notify tienen que llevar `additionalFields.parse_mode=HTML`.
- **Rotar `GOOGLE_CLIENT_SECRET` no exige nuevo refresh_token**: el token está atado al Client ID. Después del reset: mismo `GOOGLE_REFRESH_TOKEN`, secret nuevo en `.env` + `.gauth.json`, `force-recreate workspace-mcp`.
